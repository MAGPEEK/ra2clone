## 3. Derived facts (from the quotes only)

1. Row #5: the instruction at 0x7722f5 is `PUSH 0x81d9cc` (bytes `68 cc d9 81 00`, length 5, fall-through),
   Ghidra records a DATA reference from 0x7722f5 to 0x81d9cc, and `procedure = null`: in this Ghidra analysis
   no function contains 0x7722f5 (runs 1 and 4). The address 0x7729b0 is likewise outside any Ghidra
   function (run 2). That the push belongs to a weapon-type INI read "between Damage/ROF keys" and the store
   offset are NOT shown by any quote: UNVERIFIED (the spec's current wording for #5 came from a byte read).
2. Row #6: `xrefs 0x7e5264` returns an empty list (run 3), while `xrefs 0x81d9cc` lists 0x7e5264 as a
   referrer of the "Speed" string (ev_245d8c96...). So 0x7e5264 holds a pointer to "Speed" and no Ghidra
   reference (code or data) points at 0x7e5264 itself: data reference only. That the table is the "crate
   power-up name table" comes from the reference check (section 4), REFERENCE-SUGGESTED, not from tool
   output. The missing code reference is consistent with a loader that indexes the table from its base
   (0x7E523C per YRpp) in a loop, but that is an inference (UNVERIFIED).

## 4. Reference check (names only, REFERENCE-SUGGESTED)

`evidence/yrpp-src/WeaponTypeClass.h` lines 36-55 contain no ReadINI / LoadFromINI `JMP_THIS`; the only
addresses are:
```
24:	{ JMP_STD(0x772FA0); }            // FindOrAllocate
43:		{ JMP_THIS(0x7729F0); }     // CalculateSpeed
46:		{ JMP_THIS(0x772A90); }     // AllowedThreats
51:	{ JMP_THIS(0x771C70); }         // constructor
```
`evidence/yrpp-src/AbstractTypeClass.h:44`: `virtual bool LoadFromINI(CCINIClass* pINI) R0;` (virtual, no
address). The fallback address therefore came from Phobos,
`evidence/phobos-src/src/Ext/WeaponType/Body.cpp`:
```
562://DEFINE_HOOK_AGAIN(0x7729D6, WeaponTypeClass_LoadFromINI, 0x5)// Section dont exist!
563:DEFINE_HOOK_AGAIN(0x7729C7, WeaponTypeClass_LoadFromINI, 0x5)
564:DEFINE_HOOK(0x7729B0, WeaponTypeClass_LoadFromINI, 0x5)
```
i.e. Phobos hooks the exit paths of `WeaponTypeClass_LoadFromINI` at 0x7729B0 / 0x7729C7, which lie above
0x7722f5; the function start is not named in either reference. REFERENCE-SUGGESTED: 0x7722f5 lies inside
`WeaponTypeClass::LoadFromINI`.

`evidence/yrpp-src/Powerups.h`:
```
13:	DEFINE_ARRAY_REFERENCE(const char* const, [19u], Effects, 0x7E523Cu)
```
0x7e5264 - 0x7E523C = 0x28 = 10 * 4, so 0x7e5264 would be `Powerups::Effects[10]` (REFERENCE-SUGGESTED; the
spec's resolved note already places "Reveal" at 0x7e525c = index 8).
