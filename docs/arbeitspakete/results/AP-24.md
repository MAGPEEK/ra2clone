## 3. Derived facts

From the quotes alone:

1. In FUN_00712170 the `SpeedType` key (string 0x844504) is read by `CALL 0x00476fc0` with the arguments (push order) current `[EBP+0x67c]`, 0x844504, EBX (the same section/buffer argument every other INI read in this block pushes), and `ECX = ESI`; the return value (`EAX`) is stored to `[EBP + 0x67c]` (pseudocode `in_ECX[0x19f] = iVar4`). The current value at +0x67C is therefore passed as the third argument and is the value returned when the key is absent (see 2).
2. FUN_00476fc0 (0x476fc0-0x47701e): calls FUN_0048e030(buffer, 0x80) on a 128-byte stack buffer, then FUN_00528a10(param_1, param_2, <result of FUN_0048e030>, buffer, 0x80). If FUN_00528a10 returns 0, it returns `param_3` (the third pushed argument = the existing +0x67C value) unchanged (`0x477012: MOV EAX, EDI` where EDI was loaded from `[ESP + 0x94]`). Otherwise it calls FUN_0048dff0 with `ECX = buffer` (`LEA ECX, [ESP + 0x8]`) and returns its result. The function contains no string table (`referenced_strings: []`).
3. FUN_0048dff0 (0x48dff0-0x48e028): with `ECX` = the string (returns -1 when it is null), it loops over a table of 4-byte pointers starting at 0x81da58, calling FUN_007c8d20(table[i], string) for each; when FUN_007c8d20 returns 0 it returns the index `i` (EDI, starting at 0); the loop stops when the pointer reaches 0x81da78 (`CMP ESI, 0x81da78; JL`), then returns -1. The table thus has (0x81da78 - 0x81da58) / 4 = 8 entries, indices 0..7.
4. Visible entries: index 1 (pointer at 0x81da5c, Ghidra name `PTR_s_Track_0081da5c`) points to the string "Track" at 0x81dbcc. Index 0 (pointer at 0x81da58) is only named `PTR_DAT_0081da58` in the output; its string is not shown. The end bound 0x81da78 is named `PTR_s_Underground_0081da78`, i.e. the first pointer outside the scanned table points to a string "Underground"; it is never compared (loop condition `< 0x81da78`).
5. Hence: `SpeedType=Track` -> +0x67C = 1 (VERIFIED by tool output: index 1 pointer named `PTR_s_Track_0081da5c`, string 0x81dbcc "Track"). This is what Rule D's `SpeedType == 1` test uses.
6. UNVERIFIED (not in the output): the strings at indices 0 and 2..7; that FUN_007c8d20 is a (case-insensitive) string compare (only the "returns 0 on match" convention is visible from how the result is used); that FUN_00528a10 reads an INI string (its role is inferred from use; Phobos/YRpp name it `ReadString`, see section 4); the role of FUN_0048e030 (called with the buffer and 0x80 before the read; its return value is passed as the third argument to FUN_00528a10). An exact-match assumption for "Track" is also not shown (a prefix/case-insensitive compare cannot be excluded from this output).
